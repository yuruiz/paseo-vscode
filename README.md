# Paseo VS Code

Open the current Paseo workspace in a full OpenVSCode Server editor inside a desktop browser tab.
Files, editing, Git, search, terminals, and supported extensions run against the actual remote
workspace. File changes are saved directly to that workspace.

## Install

Install from the repository with a Paseo CLI that supports Git plugin sources:

```sh
paseo plugin install OWNER/paseo-vscode
```

Replace `OWNER` with the owner of this repository. Installing the plugin does not download or
start OpenVSCode Server. Follow the host setup below, then configure **Settings → Plugins →
VS Code → Editor URL** with the private URL generated by the launcher.

## Open the editor

Select **+ → VS Code** in the workspace tab bar. The editor loads directly in that tab. You can also
select **Open VS Code** in the Command Center. Keep the editor tab open and use VS Code's own file tree and Git
views to switch files and inspect diffs. There are no review snapshots or companion extensions.

The installed plugin ID is `vscode-diff`. It appears as **VS Code** in the workspace tab menu.

Embedding needs a Paseo desktop client with `navigation.openBrowser` (present in 0.9.0-beta.1).
The editor uses an Electron webview with Paseo's persistent browser profile and system proxy.
GitLens and other `openExternal` login links open in a browser tab on the Paseo client, using
the same profile so the HTTPS login callback can reach the editor. If VS Code asks to open an
external website, select **Open**. The remote daemon does not need a desktop browser.
Other clients can copy the editor link. OpenVSCode Server provides the VS Code web workbench;
extensions that require Microsoft's desktop product or proprietary services may be unavailable.

GitLens and other remote extensions share login credentials across tabs and clients connected
to the same editor user data. The launcher stores credentials in `<data>/user/secret-storage/`,
using AES-256-GCM and a separate `master.key`; the directory is owner-only and both key and database
are readable only by that OS user. Back up the whole directory together. Clients with access to
this editor user profile share its accounts, including logout. Extension credentials do not pass
through the Paseo daemon or require browser storage. Browser-only extensions keep their own
VS Code Web storage behavior.

New extension hosts use the persistent store. After changing the runtime, use **Developer:
Restart Extension Host** in an existing editor window to load it.

## Host setup

Install [OpenVSCode Server 1.109.5](https://github.com/gitpod-io/openvscode-server/releases/tag/openvscode-server-v1.109.5) on the same host as the Paseo daemon.
Clone this plugin repository for its helper scripts and run the following commands from that clone.
The launcher repairs that release's stale webview CDN pin, which otherwise prevents GitLens
webview buttons from executing commands. It preserves isolated webview origins and saves
original runtime files with a `.paseo-webview-original` suffix. Credential-storage changes keep
separate `.paseo-secrets-original` backups. The runtime must be writable.
Keep runtime and user data outside the plugin checkout. Start it with:

```sh
node scripts/start.mjs \
  --binary /absolute/path/to/openvscode-server/bin/openvscode-server \
  --data /absolute/path/to/editor-data \
  --public-url https://YOUR-HOST.YOUR-TAILNET.ts.net:8443
```

The launcher binds to loopback port 19888 and writes a private authenticated editor URL to
`<data>/connection.json`. Logs also contain authenticated URLs; keep them private.

For Tailscale Serve, forward HTTPS to that local editor:

```sh
tailscale serve --bg --https=8443 http://127.0.0.1:19888
```

Use `tailscale --socket=/path/to/tailscaled.sock serve ...` for a custom daemon socket. Serve may
need administrator privileges. Keep the remote hostname for domain-based proxy routing.

Install the plugin and enter `editorUrl` from the connection file in **Settings → Plugins → VS Code**:

```sh
npm run typecheck
paseo plugin install /absolute/path/to/paseo-vscode
```

The plugin resolves the selected workspace on the daemon and opens the editor with its actual
folder path. It does not change Paseo's transport protocol or start another daemon connection.

## Development

Use Node.js 22.13 or later. Install development dependencies with `npm ci`, then run:

```sh
npm run typecheck
npm run lint
npm run format:check
npm test
```

The remote credential store uses the Node.js SQLite implementation bundled with the tested
OpenVSCode release. Runtime fixes are version-guarded and keep backups; other editor versions
are not covered by those fixes. OpenVSCode binaries and user state are distributed separately.

Keep all editor data outside this repository. Do not publish `connection.json`, connection tokens,
credential databases or their master keys, local configuration, logs, or browser profiles.
